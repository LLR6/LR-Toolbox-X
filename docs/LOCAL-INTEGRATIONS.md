# 本地集成说明与实施状态

> 本文区分实际可执行能力与推荐入口。决定采用本地版是实施方向，不表示下面的第三方软件已安装或已接通。

## 为什么采用本地版

需要 Python、Docker 或桌面 GUI 的项目在用户电脑运行；网页能够承担的功能在浏览器运行。LR 工作台作为统一入口，逐步提供依赖检测、安装、启动、状态检查、文件输入与输出。网站不能无提示地安装用户电脑上的程序。

目标操作流程：下载并解压本地包 → 启动部署中心 → 选择工具并安装 → 检查就绪状态 → 打开工作台执行任务。系统权限、安装条款、首次模型下载和 Docker 安装可能仍需要用户操作。

## 当前已经实现

- 134 个便携 Action、已有浏览器文件工作台与 DuckDB CSV/SQL 分析台。
- 任务助手：UTF-8 文本文件导入、预设方案或模型规划、逐步/全部执行、结果查看和下载。
- 本地 Ollama 启动器：检查服务、下载默认 Qwen3 1.7B、启动回环代理及网页；Windows 脚本尝试通过 winget 安装 Ollama/Python。
- 部署包生成脚本：打包网页核心与启动器，不打包大型引擎目录或模型权重。

本机安装脚本不等于已在真实设备完成端到端验证。用户电脑性能、网络、权限、依赖版本和安装路径会影响结果。

## 尚未实现的统一部署中心

目前没有覆盖上述所有项目的安装、启动、停止、升级、日志、健康检查与卸载界面。后续实现应提供明确状态：未安装、安装中、安装失败、已安装、启动中、就绪、停止、需要处理。每个状态须来自实际检测，不得只靠按钮点击后显示成功。

安装命令必须来自维护的适配器白名单，使用参数数组调用程序，不运行模型自由生成的 shell。每个 Python 工具使用隔离环境；Docker 服务使用独立数据目录和回环端口。卸载不能默默删除用户数据。需要第三方账号、数据授权或 API Key 的工具，应显示真实要求。

## Agent 接入条件

安装与启动成功后仍需要输入 schema、输出 schema、超时、取消、错误处理和文件结果协议。只有完成适配并验证的操作才进入 Agent 工具目录。桌面窗口启动不等于 Agent 已能操作该软件。

金融工具先提供数据研究、组合记录、历史回测和模拟；不接收交易私钥，不自动下单。数据源授权、更新时间、市场、币种、复权、手续费与滑点必须明确，不能把模拟收益当作收益承诺。

## 验证标准

每项能力至少应完成：依赖缺失提示 → 真实安装或可复现部署 → 启动与健康检查 → 示例输入 → 正确输出 → 错误恢复。跨平台支持要分别报告，不能以 Linux 的语法检查代替 Windows 安装测试。

**当前结论：本地集成方向已确定；统一部署中心及资源库全部项目的执行适配尚未完成。** 后续交付应按本表逐项更新，不再把项目介绍、下载链接或启动脚本称作完整集成。
